# Frontend

- `index.html` / `home.css` / `home.js` — the cafe's homepage and **default page** (so static hosts like Vercel/Netlify serve it at "/"): hero section, a menu grid (`GET /api/menu`) and hours/location (`GET /api/faq`) loaded live, CafeBot as a floating chat widget, and a real Add to Cart button on each menu item. This is the main entry point — open it while `backend/server.js` is running.
- `cart.js` — the cart/checkout modal opened by the header's cart button or `home.js`'s "Add to Cart" buttons. Walks through cart → pickup-or-delivery → the relevant form → (for delivery) address confirmation → review → confirm, calling the real `/api/order/*` endpoints at each step. Mirrors the backend's own checkout-readiness rules (see `nextStep()`) to decide which step to show next, without needing an extra round trip. **Only works against the full backend** (`backend/server.js`) — the Vercel serverless functions in `frontend/api/` don't implement `/api/order/*` at all, since they can't hold state across requests.
- `demo.html` / `styles.css` / `script.js` — a standalone full-page chat UI, kept as a scripted demo (`demo.html`'s messages are hardcoded) for a quick visual reference. `script.js` also powers `index.html`'s real chat widget (via `POST /api/chat`) — its `API_BASE` constant near the top controls both, and it generates the shared `sessionId` that `cart.js` also uses (via `crypto.randomUUID()`, immediately on load — the order endpoints require a sessionId upfront, unlike `/api/chat` which can generate its own).
- `staff.html` — a minimal staff dashboard. Fetches saved orders from `GET /api/staff/orders` and lets staff update an order's status via `PATCH /api/staff/orders/:orderId`. Self-contained (inline CSS/JS, no build step); open it directly in a browser while `backend/server.js` is running. Edit the `API_BASE` constant near the top of its `<script>` if the backend isn't on `http://localhost:3000`.

**Note:** `home.js` and `cart.js` rely on `script.js`'s `API_BASE`/`sessionId` already being declared (it's loaded first in `index.html`) — don't add a second `const API_BASE` or `let sessionId` in either file; redeclaring across `<script>` tags throws a `SyntaxError` that silently breaks the whole page.

**Another gotcha to know about:** several elements here (`.chat-fab`, `.cart-badge`, `.cart-modal`) set an explicit `display` value in `home.css`. Because that has higher specificity than the browser's default `[hidden] { display: none }` rule, toggling their `hidden` attribute alone does nothing unless there's also a matching `.the-class[hidden] { display: none; }` override — already added for all three, but keep this in mind before adding a new toggleable element.

## Deploying this folder alone (e.g. Vercel)

This backend is a persistent Node server (`server.listen()`), which platforms like Vercel don't run — only the static files in this folder belong there. In your static host's project settings, set the **Root Directory to `frontend`** (no build command needed), and update the `API_BASE` constants in `script.js` and `staff.html` to your deployed backend's real URL (see the root `README.md`'s "Deploying" section for backend hosting options).
